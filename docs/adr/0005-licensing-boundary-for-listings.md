# 上架边界：只上自有版权或明确授权的内容

网盘里存在来源不明的商业软件，包括破解版。这类内容不进上架流水线；也不做「改文案规避平台检测」这类操作——风险来自「分发」这个行为本身，与是否收款无关。

合规闸门 `compliance.clean` 必须建立在**可核验的实物证据**上：官方仓库地址、LICENSE 文件、许可证类型，缺一不可。

## Considered options

- **上架来源不明的软件**：需求高、现货现成，但属于侵权分发。
- **只上自有版权或明确授权的**：可选品少，但可以长期做。

## Consequences

放弃了现成的高需求商品，这是有意的取舍。

一次真实的教训：2026-10-15 准备上架 ArtCraft 套件时，此前的脚本注释只写了「Apache-2.0」，而下载器只尝试了 `LICENSE` 和 `LICENSE.txt` 两个文件名、全部 404——也就是说「Apache-2.0」这个结论当时**没有实物支撑**。重新核查 GitHub API 后确认 `github.com/storytold` 组织下 13 个仓库全部为 Apache-2.0，且描述明确是 clean-room 独立重写（不是破解商业软件），真实文件名是 `LICENSE-APACHE` / `LICENSE-MIT` / `NOTICE`。

**授权结论必须落到实物。** 脚本注释里的许可声明不算证据。
