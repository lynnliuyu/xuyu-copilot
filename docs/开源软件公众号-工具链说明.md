# 开源软件公众号 · 工具链说明（W3）

> 2026-10-09 · 本文只讲**怎么用**，授权口径见 `开源软件公众号-运营方案.md`，合规流程见 `开源软件公众号-合规与下架流程.md`。
> 三个脚本都**只读本地文件 + 只访问 GitHub 公开页面**，不消耗 GitHub API 配额，也不写百度网盘。

## 0. 三个脚本一览

| 脚本 | 一句话 | 输入 | 产物 |
|---|---|---|---|
| `scripts/gh-watch.mjs` | **版本巡检**：台账版本 vs 线上最新 | `manifest.json` + `out/gh-audit.json` | `out/gh-watch.json` / `.md` |
| `scripts/gen-soft-dirs.mjs` | **网盘目录初始化方案**（只出清单，不建目录） | 上面两个 + `out/netdisk-index.json` | `out/soft-dirs-plan.json` / `.md` / `out/soft-dirs-init.sh` |
| `scripts/gen-keywords.mjs` | **关键词自动回复配置表** | 上面 + `out/soft-dirs-plan.json` + `articles/` | `docs/开源软件公众号-关键词自动回复配置表.md` / `out/keywords-table.json` |

**依赖顺序**：`gh-audit` → `gh-watch` → `gen-soft-dirs` → `gen-keywords`。
`gen-soft-dirs` 依赖 `gh-audit` 的平台/分级结论；`gen-keywords` 依赖 `gen-soft-dirs` 的「可不可给链接」判定。

## 1. `npm run gh:watch` —— 版本巡检器

### 它解决什么

「定期跟踪更新版本」是这个号**唯一的护城河**（见运营方案第 8 节），但人肉记不住 50 多个项目。
`gh-audit` 每次都把 `latestTag` 刷成「当下最新」，所以它天生看不出「我手上这版过时没有」；
`gh-watch` 的语义是**记账 vs 现况的差**：

```
台账里记的版本  ──对比──▶  线上最新版本
        │                        │
        └── 不一样 = 待更新 ─────┘
```

发布新版后重跑一次 `npm run gh:audit` 刷新台账，差异即归零 —— 这就是「台账驱动」的闭环。

### 用法

```bash
npm run gh:watch                      # 全量巡检
npm run gh:watch -- --only appflowy,obs-studio
npm run gh:watch -- --refresh         # 忽略缓存重抓
npm run gh:watch -- --concurrency 6   # 并发（默认 5）
npm run gh:watch -- --json            # 只吐 JSON 摘要（给自动化/定时任务用）
npm run gh:watch -- --no-assets       # 待更新条目也跳过产物抓取
npm run gh:watch -- --ledger out/gh-audit.json   # 换一个台账（默认就是它）
```

### 状态口径

| 状态 | 含义 | 处置 |
|---|---|---|
| `update` | 台账版本 ≠ 线上版本 | **要更新**：拉新版 → 更新网盘 → 更新合集 |
| `up-to-date` | 归一化后一致 | 无需动作 |
| `variant` | 一致，只是写法不同（`2.0` vs `2`） | 视为最新，可在台账里统一写法 |
| `no-record` | 台账里没版本号 | 重跑 `gh-audit` 补上 |
| `no-release` | 线上取不到任何 release | 人工看仓库发版策略 |
| `error` | 重试后仍取数失败 | GitHub 网页端间歇 502，**重跑即可**，不代表项目有问题 |
| `no-repo` | 非 GitHub 来源（freeware） | 版本与条款人工跟 |

### 取证通道（与 `gh-audit.mjs` 同源，免费）

1. `github.com/<repo>/releases/latest` 的 **302 Location** → `/releases/tag/<tag>`
2. **兜底**：`latest` 落空（最新版被标 pre-release → 302 到 `/releases`）时，回退读 `/releases` 页第一个 tag。
   > 这条兜底正是 W1 连续多轮挂号的需求（`krita` / `itsycal` / `aerospace` / `cyberduck` / `kdenlive` 都卡在这里），在本脚本内已实现。
3. 产物清单：`releases/expanded_assets/<tag>`（**只对「待更新」条目抓**，控制请求量）

缓存 `.cache/gh-watch/`（版本 TTL **2 小时**，`GH_WATCH_TTL_MS` 可覆盖）；网络失败**不落缓存**，下次自动重试。

### ⚠️ 与 `gh-audit` 相同的注意点

`--only` 会用**子集覆盖** `out/gh-watch.json`。要保留全量报告，跑完 `--only` 请再跑一次全量（或者先备份产物）。

## 2. 网盘目录初始化方案

```bash
node scripts/gen-soft-dirs.mjs              # 生成方案（不联网、不写网盘）
node scripts/gen-soft-dirs.mjs --only calibre,appflowy
```

产出 `out/soft-dirs-plan.json`（结构化）、`out/soft-dirs-plan.md`（给人看）、`out/soft-dirs-init.sh`（**默认为干跑**）。

### 目录规范（三层：软件名 → 平台档 → 形态）

```
仓/待售/软件/<软件名>/
  <软件名> - windows版/{便携版,安装版}
  <软件名> - mac版/          # 不分便携/安装，芯片写文件名：(Apple芯片)/(Intel)
  <软件名> - linux版/        # 格式写文件名：.deb/.AppImage
  <软件名> - android版/      # 可选
  授权说明/                  # LICENSE + 本包说明.txt +（GPL/AGPL）SOURCE-获取方式.txt
```

- 平台档**按 `out/gh-audit.json` 实测产物自动生成**，不臆造平台。
- 条目分三档：`create`（可建）/ `hold`（授权或资源待核）/ `skip`（未授予再分发权 → 只介绍，不建目录）。
- 用 `out/netdisk-index.json` 比对网盘现状，标出「目录已存在」。
- 自检：目录名不命中平台敏感词（`破解/免费/永久/全网最低/可商用`）。

### 执行建目录

`out/soft-dirs-init.sh` 默认 **只打印不执行**：

```bash
bash out/soft-dirs-init.sh            # 干跑，打印将要执行的命令
bash out/soft-dirs-init.sh --apply    # 真正执行（会写百度网盘 —— 属对外动作，需人工授权）
```

> 脚本把「基础骨架」交给既有工具 `npm run soft:tree -- init "<软件名>"`（建 windows版/mac版骨架），
> linux版/android版/授权说明 等扩展目录在脚本里以注释列出，需手工或后续给 `software-tree.ts` 加扩展参数。

## 3. 关键词自动回复配置表

```bash
node scripts/gen-keywords.mjs
```

产出 `docs/开源软件公众号-关键词自动回复配置表.md`（直接照着填公众号后台）+ `out/keywords-table.json`。

- **机器校验关键词唯一性**（50 多个关键词人工排一定撞车）。
- 自动区分三组：可给网盘链接 / 有条件 / 只介绍（**不给链接**）。
- 每个项目给出「主关键词 + 备用关键词 + 网盘目录 + 链接占位符」，占位符形如 `{{NETDISK_LINK_<id>}}`。
- 总入口关键词：`开源软件`（回复总目录 + 最新一期更新合集）。

**铁规**（来自运营方案 §7.2）：网盘链接**不进正文**，只在关键词自动回复里给；未授予再分发权的项目（`redistributable=no`）**只能给官网**。

## 4. 典型的一轮「版本回访」怎么跑

```bash
npm run gh:watch                 # 1. 看哪些项目有待更新（out/gh-watch.md 最上面）
# 2. 对 update 的条目：npm run fetch:free 拉新版 → 核对官方 sha256
node scripts/gen-soft-dirs.mjs   # 3. 确认网盘目录（保留上一版，正文记录累积不删）
npm run gh:audit                 # 4. 刷新台账（把 latestTag 追到最新，差异归零）
node scripts/gen-keywords.mjs    # 5. 若版本号进回复文案，刷新一下配置表里的版本
```

第 4 步是关键 —— **不重跑 `gh-audit`，`gh-watch` 会一直报同一个「待更新」**。
