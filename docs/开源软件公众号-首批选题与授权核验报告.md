## 二、核验推翻了清单里的两处登记

这两条清单里都写着 **MIT**，实际读出的是 **GPL-3.0**：

| id | 项目 | 清单登记 | 实际读出 | 依据文件 |
|---|---|---|---|---|
| `alt-tab` | AltTab | MIT（开源） | **GPL-3.0** | `LICENCE.md` |
| `lossless-switcher` | LosslessSwitcher | MIT（开源） | **GPL-3.0** | `LICENSE` |

**为什么这事必须纠正，而不是"反正都能打包"：**

MIT 与 GPL-3.0 的**分发义务完全不同**。按 MIT 的理解打包发出，就会漏掉 GPL 的源码提供义务 —— 而这是可以被投诉的实打实的违规。清单登记错了，等于给后面的打包环节埋了一个雷。

> 💡 顺带一提，`alt-tab` 的许可证文件是英式拼写 `LICENCE.md`；`MonitorControl` 用的是 `License.txt`（大小写混合）。**第一版体检器就是在这两个上翻车的** —— 候选名写死成全大写，在大小写敏感路径上直接 404，把 MIT 项目误判成「无许可证」。现已改为**先从文件树读出真实文件名**，再按精确名取。

## 三、两条需要人工拆分资源（F 级）

F 级 = **代码本身可分发**，但仓库顶层出现了可能夹带第三方授权的目录。

### `bongocat` — 真正的信号

```
仓库顶层：vendor/cubism/5-r.5   ← Live2D Cubism SDK
```

这是**货真价实的第三方组件**。Live2D Cubism SDK 有独立的授权条款，跟主项目声明的 Apache-2.0 是两回事。虽然项目是开源的，但**打包前必须单独确认 SDK 的授权范围**。

### `alt-tab` — 需要看一眼

```
仓库顶层：vendor   ← 通常装的是 Sparkle 之类的更新框架
resources
```

`vendor` 目录在开源项目里很常见，多半是依赖库。但既然出现了，就顺手确认一次，别猜。

> ⚠️ **第一版体检器在这里误报了 7 条**。原因是把 `assets/` `resources/` `icons/` 也算成高风险 —— 那些目录装的是应用自己的 UI 资源，跟主协议走。误报一多报告就没人看了，所以现在**只认强信号**（`vendor` / `third-party` / `licenses` / `fonts` / `models` / `weights`），其余降级成提示。

## 四、五条非 GitHub 来源的条目

这些在清单里以「免费软件」登记，**没有仓库，授权无法自动核**。

| id | 项目 | 清单登记 | 官方直链 | 建议 |
|---|---|---|---|---|
| `xnviewmp` | XnViewMP | 免费软件（官方允许免费使用与分发） | HTTP 200 | 人工确认条款是否含**再分发**授权 |
| `mediainfo` | MediaInfo | BSD-2-Clause（开源） | HTTP 200 | ⚠️ **应补登 repo** |
| `mediainfo-gui` | MediaInfo GUI | BSD-2-Clause（开源） | HTTP 200 | ⚠️ **应补登 repo** |
| `mp3tag` | Mp3tag | 免费软件 | 直链待核实 | 确认后人工核条款 |
| `runjs` | RunJS | 免费软件 | 直链待核实 | 项目已迁移，先补地址 |

**MediaInfo 这两条是明显的登记疏漏**：清单里自己写着「BSD-2-Clause（开源）」，却没有填 `repo` —— 说明它本来就是开源项目，只是当初按"官网直链"登记的。补上仓库地址后即可纳入自动体检和版本跟踪。

> **核对提醒**：`免费软件 ≠ 可再分发`。XnViewMP、Mp3tag、RunJS 这类必须逐个读官方条款 —— 允许免费使用，不等于允许你把安装包转存到自己的网盘再分发。

另有一条 `cog`：清单备注「kode54/Cog 仓库已迁移，需确认新地址」，`repo` 字段为空，本次无法核验。

## 五、⭐ 打包时的分发义务（最容易漏的一节）

能不能分发只是第一步。**下面这组义务如果没有随包落实，前面 15 条「可打包」就是纸面上的。**

| 分发义务 | 涉及条目 |
|---|---|
| **GPL：须附源码获取方式（或源码）+ 完整许可证文本** | `calibre` `dockdoor` `lossless-switcher` `easydict` `tiny-rdm` `lulu` |
| **AGPL：须提供完整源码（含网络服务场景向用户提供）** | `quickrecorder` |
| **Apache-2.0：保留版权声明与许可证全文，有 NOTICE 须一并携带** | `sniffnet` `switchhosts` |
| 保留版权声明与许可证全文（随包放 LICENSE） | `maccy` `monitorcontrol` `fsnotes` `stats` `neohtop` `tabby` |

**两个高频错误：**

1. **GPL 家族只丢一个二进制出去 = 不合规。** 7 条里有 6 条是 GPL，必须在包里放 `SOURCE-获取方式.txt`，写清原始仓库地址和对应版本 tag。这是最常见的疏漏。
2. **AGPL 的义务比 GPL 更重**（`quickrecorder`）。它是 15 条里唯一一个 AGPL —— 虽然对"分发二进制"这个场景，做法和 GPL 一样（附源码获取方式），但要知道它多一层网络服务场景的义务，别在描述里写成"和 GPL 一样"。

## 七、工具：`npm run gh:audit`

```bash
npm run gh:audit                        # 全量体检（走缓存，约十几秒）
npm run gh:audit -- --refresh           # 忽略缓存重抓
npm run gh:audit -- --only maccy,stats  # 只跑指定条目
npm run gh:audit -- --api               # 额外拉 API 元数据（配额感知，可选）
npm run gh:audit -- --list              # 只列清单，不联网
```

**选它而不是调 GitHub API 的原因**：未认证的 `api.github.com` 只有 **60 次/小时**，跑二十几个项目就被限流。所以全部改走免费通道 —— 读许可证全文、读仓库页文件树、追踪 releases 重定向，**一次配额都不花**，还能把"实际读到的许可证正文"作为取证留档。

缓存目录 `.cache/gh-audit/`（已 gitignore）：许可证 7 天、文件树 12 小时、版本信息 6 小时。
