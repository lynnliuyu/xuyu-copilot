# 竖版视频制作说明（图文转视频）

> 一条命令产出 1080×1920 / 30fps 的竖版视频，全程自动、不用录屏、不用剪辑。
> 配套：`docs/开源软件公众号-封面模板使用说明.md`（视觉体系同源）· `docs/开源软件公众号-推广与冷启动方案.md`（渠道策略）

---

## 一、一条命令

```bash
npm run video -- assets/video-specs/maccy.json
```

产物全部落在 `out/video-<id>/`：

```
out/video-maccy/
├─ cards/                   6 张卡片 PNG（1080×1920）+ _总览.png
├─ maccy-竖版.mp4           成片（约 26 秒 / 5 MB / 静音）
└─ 发布文案.md              标题候选 + 正文 + 话题标签，可直接复制
```

只想改文案重出卡片（不重跑视频）：

```bash
npm run video:cards -- assets/video-specs/maccy.json
```

## 二、四步流水线

| 步 | 脚本 | 干什么 |
|---|---|---|
| ① | `scripts/render-video-cards.py` | 按 JSON 规格渲染 6 张竖版卡片 |
| ② | `scripts/verify-video-cards.py` | **自动核验排版**：越界 / 顶到页脚 / 空白卡 |
| ③ | `scripts/make-video.mjs` | 每张卡加缓慢推拉 → 段间交叉溶解 → 导出 MP4 |
| ④ | `scripts/verify-video-frames.py` | **抽帧回比**：每段抽一帧，确认"最像它自己那张卡" |

②④ 是**不需要肉眼的验收**。这一步很关键——卡片多了以后靠人看必漏，而且我（或你）看漏一次就是发出去一条错的。

## 三、六种版式（固定顺序）

| # | type | 干什么 | 必备字段 |
|---|---|---|---|
| 1 | `hook` | 封面钩子 | `kicker` `titleLines` `sub` `stat{value,label}` `badge` |
| 2 | `pain` | 痛点（用"记录行"示意） | `kicker` `titleLines` `rows[{text,tag}]` `note` |
| 3 | `features` | 功能 ✓ 清单 | `kicker` `title` `items[]` |
| 4 | `facts` | **实测事实（最值钱）** | `kicker` `title` `facts[{value,label}]` `note` |
| 5 | `steps` | 安装三步 | `kicker` `title` `steps[{t,d}]` |
| 6 | `cta` | 引导（账号名 + 关键词） | `kicker` `titleLines` `account` `keyword` `note` |

每张卡还可带：

- `dur` — 这张显示几秒（默认 5）。**全片控制在 24–28 秒**（六张卡，每处交叉溶解再扣 0.6s）——再长完播率就掉。
- `zoom` — `in` 推近 / `out` 推远（交替看起来更活）
- `footerRight` — 右下角小字，建议写 `01 / 06` 这种页码（暗示"后面还有"，提升完播）

> ⚠️ **第 4 张（facts）是最容易被忽略、但最值钱的一张。**
> 体检器看到的是元数据，解包看到的才是真相 —— "已通过 Apple 公证，不用绕 Gatekeeper""通用二进制""最低 macOS 14"这类事实，
> 是让人从"有点兴趣"变成"我现在就去下"的关键。别把它做成泛泛的"三大亮点"。
>
> ⭐ **但只放 2 条**（其余降级成一行 `note`）。4 条并列会被读成"再看一遍正文"。相应地：
> `facts` 在 **≤2 条时自动改单列整行 + 放大字号**（`card_facts` 里的 `single` 分支），`features` 在 **≤3 条时字号提到 66px**。
> **条目少了，唯一的解法是字变大** —— 靠拉行距只会把空白挪到行内，卡片看着还是空。
>
> ⭐ **验收有留白阈值**：正文底边到页脚 **>320px 就报「空（内容没撑满）」**。
> 视频卡的留白和图文卡相反 —— 图文留白是呼吸感，**视频留白是"没做完"**，观众会以为画面没加载出来。

## 四、视觉规范（改代码时别破坏）

| 角色 | 值 |
|---|---|
| 底色 | `#0E1116` 近黑 |
| 强调 | `#C8FF3D` 酸绿 |
| 辅助 | `#8B94A3` 灰 |
| 字体 | Noto Sans SC（可变字重 400 / 500 / 700 / 900） |

**字号底线 28px**，放不下就删字，不要缩字号。

**为什么视频卡要"自适应布局"而不是固定留白**：图文卡留白是呼吸感，视频卡留白就是"空"——观众会觉得画面没做完。
所以 `render-video-cards.py` 里有一套 `distribute()`：把内容块在「页眉下方 ~ 页脚上方」之间按可用高度撑开（行高/间隔在合理区间浮动）。

---

## 五、音乐：**不要在视频里带**

导出的 MP4 是**静音**的，这是刻意的：

1. 视频号 / 小红书都自带音乐库，**用平台音乐不吃版权**；
2. 用了平台音乐还能进「用同款音乐」的流量池，等于白捡一次曝光；
3. 你自己塞音乐，反而可能被静音或限流。

**发布时在 App 里挂音乐。** 节奏快的工具类内容，选轻电子/律动感强的。

## 六、换一个软件要做什么

只改 JSON，视觉不用动：

1. 复制 `assets/video-specs/maccy.json` 改名，比如 `iina.json`；
2. 把 6 张卡的文字换掉。**事实数据一律从 `out/gh-audit.json` 取**（版本 / 协议 / 平台 / star），不要凭印象写；
3. **解包一次**，把 `facts` 那张卡换成解包才知道的事实（体积、架构、是否公证、最低系统）；
4. 跑 `npm run video -- assets/video-specs/iina.json`。

> 第 3 步别跳。跳过它，第 4 张卡就只是"官方宣传语的搬运"，说服力直接掉一半。

## 七、环境依赖

| 依赖 | 位置 | 说明 |
|---|---|---|
| ffmpeg | `~/.workbuddy/binaries/node/workspace/node_modules/ffmpeg-static/ffmpeg` | 静态包，**不污染系统**。`FFMPEG` 环境变量可覆盖 |
| Pillow | `~/.workbuddy/binaries/python/envs/default/bin/python` | 隔离 venv |
| 字体 | `.cache/fonts/NotoSansSC-VF.ttf` | Noto Sans SC 可变字重（SIL OFL），可用 `CARD_FONT` 覆盖 |

**为什么不用本机字体**：本机只有苹方系 / 冬青黑，**没有思源的粗黑**，封面模板要的那种大黑字出不来。
Noto Sans SC 与思源黑体是同一套字（只是名字不同），且是开源协议，可以放心随包分发。

## 八、还没做的

- **配音 / TTS**：现在是纯字幕无解说。要加旁白得先定声音来源（真人录 or TTS），且 TTS 的商用授权要单独核。
- **录屏后期线**：真人录屏 → 切片 → 加字幕 → 卡节奏 → 压制。这是"视频号主内容"的正路，成本在录屏那一步，目前没搭。
- **批量出片**：65 条候选池如果都要出竖版视频，现在得一条条改 JSON。可以再做一层"从 `out/gh-audit.json` 直接生成 spec"的自动化。
