一、总体结论

这个需求技术上成立，但它不是一件事，而是四件事拼起来：网盘盘点归类、资源选品定价、闲管家上架、订单自动发货。把它们串成一条链的最佳形态是：以「资源中台 + 闲管家适配层」为核心的自研系统，AI 通过 MCP 直接操作网盘，用 n8n 做可视化编排和人工审批闸门。

可行

网盘列表 / 搜索 / 移动 / 上传 / 分享、闲管家商品上架、订单推送、自动发货，全部有官方接口。

有门槛

百度网盘「创建分享链接」是付费接口且仅企业开发者可用。这是自动发货链路的命门，必须先解决。

要设计

网盘应用只能操作 /apps/{appname} 目录。整个资源仓必须建立在这个目录之下。

三、三条接入路线（关键决策）

闲管家的「自动发货」有两条天然通路，加上百度侧的一种偷懒做法，一共三条。选错会白干一遍。

路线做法优点代价结论
A · 商家自研 ERP
推荐主线		 自己开店，用开放平台 API 全流程：创建商品 → 上架 → 收订单推送 → 调发货接口 一套 appKey 全控；能用上「批量创建商品」，最容易做全自动上架 需订购闲管家开放平台版本；商品字段多且强校验，联调成本高 主线
B · 虚拟货源平台 把自己注册成闲管家的「货源方」，闲管家调你的「创建卡密订单」接口，你返回发货内容 发货逻辑最干净；一套货源可服务多个闲鱼商家（可做成生意） 要按货源标准实现 10+ 接口，并接受闲管家的签名与回调规范 二期扩展
C · 卡密池托管 只把「分享链接 + 提取码」批量灌进闲管家的卡密仓库，用闲管家原生自动发货 零发货代码，最快跑通收入闭环 卡密静态预置，无法一单一链、无法动态追溯、链接泄露难控制 先跑通用它

建议路径：C 先跑通 → A 做全自动化 → B 做规模化

先用路线 C 在 1～2 天内跑出第一笔真实成交（验证商品能上架、能发货、能收款），再用路线 A 把「上架 + 发货」全部自动化，最后如果这套系统好用，再注册货源身份走路线 B，把同一套内核卖给其他闲鱼商家。三条路线共用同一个「资源中台」，只是换适配器，不会返工。

5.2 三个必须在 MCP 层就做对的设计

权限分档

把工具分成 read / write / money 三档。AI 调 money 档（创建分享、发布商品）时必须显式确认，且默认 dry_run=true 只回执不执行。

Token 管家

单独进程持有 token：启动校验 → 接近过期自动刷新 → 刷新失败发告警并停止写操作。绝不让 AI 拿到 refresh_token。

审计日志

每次调用落一条 task_log（工具名、参数指纹、耗时、errno、request_id）。百度返回的 request_id 一定存下来，出问题凭它申诉。

路径守卫

所有 path 参数强制校验是否落在 /apps/{appname} 前缀内，越界直接拒绝——避免撞上平台的权限错误反复试错。

六、L3 · AI 分类与选品引擎

6.1 三级流水线

1
规则预分（快、免费、先做）按扩展名 / 关键词 / 大小 / category 字段粗分。成本几乎为零，能砍掉 60% 的噪声。
2
LLM 语义归类（准、贵、后做）把「文件名 + 大小 + 目录路径 + 同类兄弟文件」打包成批次喂给模型，输出主题树与标签。按批处理而非逐文件，控制成本。
3
可售性打分（决定上不上架）四个维度加权：版权洁净度（命中禁售词/破解特征直接归零）、内容完整度（是否缺章节/分卷）、需求热度（类目竞品密度）、交付便利度（体积与分享成本）。

6.3 去重与指纹

网盘返回的 md5 是云端哈希、不是文件真实 MD5，只能当弱指纹。组合指纹建议：规范化文件名（去版本号/番号/后缀）+ 文件大小 + 目录路径 + 云端 md5。对高价值候选再抽样下载做真实哈希校验。

十一、技术选型与目录结构

核心服务：Node + TypeScript

MCP SDK 是 TS 生态；闲管家签名是纯 MD5，Node 内置 crypto 就够；和 MCP 工具层共用类型定义，一套代码两种出口。不建议用 Python 重写一遍网盘客户端。

控制台：Next.js

复用你熟悉的栈。页面：资源库、选品队列、商品草稿审批、卡密池、订单台账、工作流开关、告警中心。

编排：n8n（Docker 自托管）

可视化、可热改、有 Wait 审批节点、自带 cron 与 webhook。部署在腾讯云 CVM 上，与主服务同机不同容器。

图片与部署

图片托管用腾讯云 COS（已有账号）。服务部署到你现有的腾讯云 CVM；未来可迁 CloudBase。

十三、风险与合规（别跳过）

四个真实风险

  1. 版权风险（最高）——卖网盘里的课程/软件/电子书极易构成侵权。闲鱼有明确的禁售商品范围，盗版资源属于重点打击对象，轻则商品下架，重则封店并可能承担法律责任。建议只上架自有版权或已获授权的内容，把「洁净度=禁售」做成硬闸门而不是建议。
  2. 平台条款风险——百度网盘开放平台规范明确禁止「多人共享个人网盘账号及会员权益」等行为，把网盘资源批量商业化需要你自己评估边界，并严格遵守开放平台规范。
  3. 资质阻塞风险——文件分享接口需企业认证 + 付费购买。如果无法完成，自动发货链路直接不成立，项目要立刻转向其他交付方式（如自有对象存储直链+自有站点）。
  4. 账号与资金风险——闲鱼虚拟商品退款纠纷高发。务必在商品描述里明确交付方式与退款政策，保留发货证据（订单号↔链接↔时间戳）。

A4 · 最硬的证据：错误码表里的 13998

来源：《文件分享服务（新）› 错误码说明 › 公共错误码》
https://pan.baidu.com/union/doc/基础网盘服务/文件分享服务新/错误码/（更新时间 2026-09-09）

errno错误信息错误描述

这条错误码是整套论断的落点：分享能力不是拿到 access_token 就能用，而是要单独「申请开通权限」。也就是说，即使你完成了 OAuth 授权、token 有效，未开通分享权限的调用仍会直接返回 13998。

A5 · 顺带确认的两条附加限制

版本限制（《接入指南 › 使用限制》）：「文件分享类接口与百度网盘企业版不互通，不支持创建或者获取企业版分享的链接内容。」

频次限制：「分享接口会根据用户调用行为有限制措施，但能满足用户的正常使用行为。」

需要说明的两点边界

  1. 关于「旧分享服务」：官方简介里提到「（注：旧的分享服务不支持）」加强权益附送，说明历史上存在过一套旧分享能力。但当前官方文档目录里只有《文件分享服务（新）》这一套，旧的 /rest/2.0/xpan/share?method=rapidshare 已不在文档树中，只在第三方博客里被提到。不要把项目建立在非文档化的旧接口上——它随时可能失效，且平台明令禁止绕过限制。结论按「新分享服务」为准。
  2. 关于购买方式：没有公开价目表与自助开通入口，只能通过客户经理企业微信或 ext_mars-union@baidu.com 走商务对接，回复周期 1～3 个工作日。这意味着排期上要留出商务沟通时间，不是点一下就开通。

下一步建议：先做 P1（网盘打通 + MCP 工具层），它不依赖任何资质审批，可以立刻开工，并且做完之后你马上就能用自然语言盘点网盘。等 P0 的资质批下来，P4 的发货链路直接接上去即可。
