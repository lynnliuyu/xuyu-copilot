## 一、先说清楚：哪些我能做，哪些只能你做

这条最重要，先看，免得互相等。

| 环节 | 谁做 | 说明 |
|---|---|---|
| 选品 / 协议核验 / 打包说明 | 我 | `gh:audit` 自动体检 |
| **封面图** | 我 | 一条命令出 2.35:1 首图 + 1:1 方图 |
| **正文排版** | 我 | md → 内联样式的公众号 HTML，粘贴即用 |
| **发布清单** | 我 | 标题 / 摘要 / 关键词 / 检查项 |
| 关键词自动回复 | 已就绪（我维护） | 关注欢迎语 + 关键词 + 目录，已实测 |
| **生成网盘分享链接** | **你**（或授权我） | 要先上传到网盘；分享走**付费接口** |
| **登录公众平台点发布** | **只能你** | 见下 |

**为什么发布这一下我替不了你**：个人订阅号**没有发布接口**（`freepublish/submit` 只对认证号开放），而且发文必须**扫码登录**你的公众平台。所以我的定位是——**把东西备到"你点了就能发"**，而不是替你按下那个按钮。

## 三、发布前闸门：**下载链接必须先就位**

**这是当前唯一没通过的项。**

跑 `npm run mp:verify` 会看到：

```
⛔ 下载闸门未开：关键词 `Maccy` 对应的网盘链接还没配
   → 现在发出去，读者回复关键词只会拿到「[网盘链接占位]」
```

**为什么这是硬闸门**：文章第 ⑩ 节自己写着「不用『先关注后给空链接』那套」。链接没配就发，等于第一篇就打自己的脸。

### 真实链路（已实测跑通）

关键认知：**分享链接和关键词回复表是两套数据，中间靠一个同步器打通**。分享链接在 `out/netdisk-shares.json` 台账里（已有 **774 条**，`软件/` 下 22 条），但关键词回复读的是 `assets/free-software/netdisk-links.json` —— 这张表原来是空的，所以闸门一直关着。

```
1. 包上网盘         npm run push:free
2. 补授权说明       npm run push:license                ← ⭐ LICENSE 全文，MIT/GPL 的硬义务
3. 建分享链接       npm run share:netdisk -- --cat 软件   ← 已建过的自动跳过，不重复建
4. 同步进回复表     npm run share:sync                  ← ⭐ 关键一步，别手工填
5. 验证             npm run mp:verify
```

### 第 2 步为什么不能省

`push:free` 生成的 `使用说明.txt` 里**只写了许可证名称**（「许可　MIT」），**不含许可证全文**。

- **MIT 的唯一条义务就是「分发时必须附版权声明与许可证全文」** —— 只有 `使用说明.txt` 的包，在这个意义上**是不合规的**；
- **GPL / AGPL 更严**：还要附**源码获取方式**（`SOURCE-获取方式.txt`）。

四篇文章的 ⑩ 节都承诺了「授权说明」——`push:license` 负责兑现。

链路：`make-source-note.mjs` 从**本地体检缓存**抄出许可证正文（不联网、不编造，缓存缺失就标"缺"而不是猜）→ `push:license` 上传到 `软件/<产品名>/授权说明/`。

**行为上有两条保证**（这是它敢在已有目录上跑的原因）：

- **只新增文件，绝不删除或覆盖已有内容**；
- 上传前先 `ls` 目标目录，**已存在的同名文件跳过** → 可安全重跑，不会堆出 `(1)` 副本。

> 💡 新增文件**不影响已生成的分享链接** —— 百度按 `fs_id` 记录分享，分享的是目录，新增子文件自动包含在内，不需要重建分享。

`share:sync` 做三件事：从台账读 `软件/<产品名>` 的链接 → 用 manifest + 体检产物把**网盘文件夹名映射成项目 id**（`MediaInfo GUI` → `mediainfo-gui`）→ 写进回复表。

- 默认**只补空位**，已有值不动；要覆盖加 `--force`
- 映射不上的会列出来，**不静默丢**
- 改完**不用重启服务**（按文件 mtime 热加载）

> ⚠️ 别手工填 `netdisk-links.json`：网盘文件夹名和项目 id 不是同一个东西，手填迟早错位，而且新增分享后又得再填一遍。

**实测效果**（回复关键词拿到的真实内容）：

```
【Maccy 2.7.1 · 剪贴板历史（轻量）】

📦 下载（本号转存的官方原包，含授权说明与校验值）
https://pan.baidu.com/s/1r6SJIwfR3Ez5mwuR5aOLmg
提取码：ejez

🔗 原项目地址：https://github.com/p0deje/Maccy
好用记得去点个 Star，支持原作者。
```

## 四、注册（还没有正式号才需要这一节）

个人订阅号：身份证 + 手机号 + 邮箱，免费，当天可开通。

⚠️ **注册前先想好名字，因为公众号名称一年只能改 2 次。**

- 本号用名：**繁梦开源小仓库**（含品牌前缀，撞名概率低于「开源小仓库」这类通用名）

- 名称里**不能含「公众号」三个字**（平台规则），现有名字已避开

## 五、一次发布的完整步骤

| # | 动作 | 注意 |
|---|---|---|
| 1 | 浏览器打开 `out/mp/<id>/发布操作台.html` | 用 Chrome / Edge，别用 Safari 粘贴（样式丢失概率高） |
| 2 | 按页面上的 1→6 依次复制：标题 / 作者 / 摘要 / 封面 / 正文 / 关键词 | 每个字段都有独立的复制按钮，**不用手动选文本** |
| 3 | 公众平台 → 内容与互动 → **新建图文** | |
| 4 | 填**标题**（抄 `发布清单.md`） | 列表里大约只显示前 20 字，核心信息放开头 |
| 5 | 填**作者**：繁梦开源小仓库 | |
| 6 | 填**摘要** | ≤120 字，清单里有现成的 |
| 7 | **上传封面** → 选 `首图-1800x766@2x.png` | 编辑器会让你裁剪两处，见第六节 |
| 8 | 正文区 **Ctrl+V** 粘贴 | 样式会一起带过去；粘完**上下滚一遍**，确认表格卡片没散 |
| 9 | 开**原创声明**（有资格才开） | 没资格就先不开，**不要伪造** |
| 10 | **预览 → 发给自己微信**，在手机上读一遍 | 手机上和电脑上差别很大，这一步别省 |
| 11 | 确认无误 → **群发** | |

## 六、公众号封面的两个坑

**① 同一张图，不同位置裁切方式不一样。**

- 订阅号消息列表里是 **2.35:1 横幅**
- 转发到聊天 / 朋友圈时按 **1:1 居中裁切**

所以标题必须**水平居中**、且落在中间 383px 宽的方形区内。本套封面生成器**已经按这个约束自动定字号**（渲染时会打印「居中裁切不会切字 ✅」）。你改标题时如果变长，字号会自动变小——这是设计，不是 bug。

**② 正文内容宽度是 677px。**

`preview.html` 就是按 677px 渲染的，所以你在预览里看到的换行位置，跟手机上基本一致。

1. 公众号后台 → **设置与开发 → 基本配置 → 服务器配置**
2. 填：

> 想知道配的是哪个号：日志里不体现（服务对账号无感知），记在 `assets/mp-config.json` 的 `accountId` 字段里。

| 回复 `开源软件` | 全量目录 |

## 九、常见故障

| 现象 | 原因 / 处理 |
|---|---|
| 粘进去样式全没了 | 用了 Safari，或没点「复制正文」而是 Ctrl+A。换 Chrome 重来 |
| 表格散了 | 本转换器已把表格转成卡片（公众号对 `<table>` 支持不稳），若仍散，把该段删掉重粘 |
| 封面被裁掉字 | 标题太长。改短，或改 `assets/mp-covers/<id>.json` 重新渲染 |
| 回复关键词没反应 | 检查服务器配置是否启用、Token 是否一致；本机 `lsof -nP -iTCP:8899 -sTCP:LISTEN` |
| 回复拿到「[网盘链接占位]」 | 链接没配，见第三节 |
