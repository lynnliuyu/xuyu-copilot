# 发布节流 300 秒，护栏放在服务端

曾经用 `--every 20` 一次性推了 275 条商品，结果约 405 个在售商品被平台下架（在售数从 450 掉到 152）。此后定下规矩：单条间隔不小于 300 秒，分批推送。

节流与体检闸门实现在服务端 `packages/xgj-admin/src/publish-guard.ts`，并在调用平台接口**之前**取号。之所以不放前端，是因为前端按钮可以被绕过——脚本可以直接调接口。

## Considered options

- **前端限流**：实现简单，但任何直接调接口的脚本都能绕过。
- **服务端限流**：所有调用路径（页面、脚本、队列、定时任务）都经过同一个闸门。

## Consequences

批量上架变得很慢：14 条要跑约 65 分钟。这是刻意接受的成本，换来的是不再出现批量下架。

推论：**任何探测脚本都不能用小于 300 秒的间隔**。用 `--every 60` 探测时，第 2、3 个请求会被本地护栏拦下，看起来像失败，其实是自己拦自己。探测请用 `--every 310 --limit 3`。
