> 2026-10-08 · 以 Topaz 系列为样本实测
> 涉及：`423down.com` 站点结构、Mac 版来源、网盘目录规范

## 一、423down 是什么 —— 结论：Windows 站，全站无 Mac

**你的判断是对的。** 三条证据：

| 检查 | 结果 |
|---|---|
| 导航分类 | 图形图像 / 多媒体 / 办公软件 / 下载类 / 原创类 / Android / AI智能体 / 系统辅助 / 实用软件 / 浏览器 / 硬件工具 —— **没有 Mac 栏目** |
| 搜 `Mac` | 只返回 2 条：`Macrorit分区专家`、`MacType` —— **都是 Windows 工具，只是名字里带 Mac** |
| 搜 `dmg` | 零结果（页面回落到"最新发布"兜底列表） |

所以 **Mac 版必须另找来源**。

### 站点结构（采集要用到的）

```
关键词搜索   https://www.423down.com/search/<关键词>
分类/标签页  https://www.423down.com/image/topaz      （/image 图形图像、/multimedia 多媒体…）
文章页       https://www.423down.com/<id>.html        （id 是纯数字）
```

**关键粒度：一篇 = 一个软件 + 一个版本快照 + 一种打包形态。**
文章是"版本"的粒度，不是"软件"的粒度 —— 这就是你看到"同名多篇"的直接原因。

### 文章页下载区的固定三组

以 `Topaz Video AI v7.1.5`（id 14531）为例，下载区**全部是普通文字链接，不是按钮**：

| 组 | 内容 | 示例 |
|---|---|---|
| ① 网盘镜像组 | 123云盘 / 蓝奏云 / 百度网盘 / 夸克 / 光鸭盘 | `pan.baidu.com/s/1OCoSSYPZZQdgJ3AG7JZiOQ?pwd=2023` |
| ② 官方直链组 | 原版安装包 | `downloads.topazlabs.com/.../TopazVideoAI-7.1.5.msi` |
| ③ 补丁组 | 汉化补丁 / Crack Fixed / 去水印补丁 | 蓝奏云 `423down.lanzouo.com/...` |

> ⚠️ **所有外链都被包一层**：`https://www.423down.com/go.php?url=<URL的base64>`
> 采集时必须解 base64。已实测解码正确。
> 另一个细节：**百度网盘的提取码长期固定为 `2023`**，可以直接写死兜底。

## 二、为什么"同名有不同版本" —— 三层原因，只有第一层是真坑

### 1. 产品代际更名 + 版本号重置 ⚠️ 最容易踩

Topaz 在 2026 年把产品**去掉了 AI 后缀，并重置了版本号**：

| 旧名（2025） | 新名（2026） |
|---|---|
| Topaz Video AI 7.x | **Topaz Video 1.x** |
| Topaz Photo AI 4.x | **Topaz Photo 1.x** |
| Topaz Gigapixel AI 8.x | **Topaz Gigapixel 1.x** |

**后果：版本号不能跨代比较。** `7.1.5` 数字上比 `1.7.1` 大，但它其实更旧。任何"按版本号排序取最新"的自动化都会取错，必须**带上代际名一起判断**。

### 2. 产品合并 / 停更

`DeNoise AI`、`Sharpen AI`、`Video Enhance AI` 已分别并入 `Photo AI` / `Video AI`，官方不再更新。站内还留着，属"历史产品"。

### 3. 打包形态不同（站内"多篇"的主因）

同一版本会拆成多篇文章发布不同打包：
`绿色便携版` / `绿色版` / `中文直装版` / `中文汉化版` / `官方正式版` / `破解版`

## 三、Mac 侧来源

### 结论：走「官方安装包 + 第三方补丁」

官方下载页给的是**按平台分的固定入口**，跟着重定向就能拿到真实资产地址，不用猜文件名：

```
https://topazlabs.com/d/<slug>/latest/mac/full        → Apple 芯片
https://topazlabs.com/d/<slug>/latest/mac/intel/full  → Intel 芯片
https://topazlabs.com/d/<slug>/latest/win/full        → Windows
https://topazlabs.com/d/<slug>/latest/win/arm/full    → Windows on ARM
```

### 实测结果（2026-10-08）

| 产品 | slug | Apple 芯片 | Intel 芯片 | Windows |
|---|---|---|---|---|
| Topaz Video | `videostudio` | `TopazVideo-1.7.1.pkg`（1.54 GB） | **已不提供** | `TopazVideo-1.7.1.msi` |
| Topaz Photo | `photostudio` | `TopazPhoto-1.7.0-arm64.pkg`（1.20 GB） | `TopazPhoto-1.7.0-x86_64.pkg`（694 MB） | `TopazPhoto-1.7.0.msi` |
| Topaz Gigapixel | `gigapixelstudio` | `TopazGigapixel-1.3.6-arm64.pkg`（680 MB） | `TopazGigapixel-1.3.6-x86_64.pkg`（180 MB） | `TopazGigapixel-1.3.6.msi` |

### ⚠️ 三个反直觉点（都踩过，别再猜）

1. **Mac 安装包是 `.pkg`，不是 `.dmg`。**
   照经验猜 `.dmg` 会拿到 403。注意 `TopazVideo-1.7.1.dmg` 恰好也存在，容易误判成"猜对了"——**以官方入口的重定向结果为准**。
2. **不同产品对 Intel Mac 的支持不一样。**
   `Topaz Video` 的 `mac/intel` 返回 **404**（已放弃 Intel Mac），而 Photo / Gigapixel 仍同时提供 `arm64` 与 `x86_64`。不能统一假设。
3. **UA 只能用简版。** topazlabs.com 前面有 Cloudflare 规则：

   | 请求头 | 结果 |
   |---|---|
   | `User-Agent: Mozilla/5.0` | 200 ✅ |
   | 完全不带 UA | 200 ✅ |
   | 完整 Chrome UA（加不加 `Accept` 都一样） | **403** ❌ |

   所以采集器里故意用 `Mozilla/5.0`，别顺手改成"更像浏览器"的那种。

4. slug 不是产品显示名：Photo 的 slug 是 `photostudio`，Gigapixel 是 `gigapixelstudio`。而实际部署路径又是另一回事（`TopazPhoto/…`，**不是** `TopazPhotoStudio`）。

### 第三方 Mac 站（补丁 / 整包的来源）

官方只给干净的原版安装包，**激活补丁必须另找**——所以这条路线是「官方包 + 第三方补丁」。

| 站点 | 情况 |
|---|---|
| **torrentmac.net** | 版本最新（Topaz Photo 1.7.0），附带 `Patch.command` 安装说明 |
| **filecr.com/macos** | 历史版本最全（Topaz Photo AI 4.0.3 / 4.0.1 / 3.6.2 / 3.6.1 / 2.2.0） |
| **macw.com** | 中文站，Topaz Photo Pro v1.7.0 激活版（下载需积分） |
| **repackmac.com** | Topaz Photo Pro 1.2.1 for Mac |
| **macat.vip** | **你已经在用** —— 网盘里的微信小助手插件就来自这个站的打包 |

> 这几个站**不做自动抓取**：多有人机校验/积分门槛，且需要人工确认包内没有夹带。
> 需要时人工下载后放进对应目录即可。

## 四、网盘分类方案

### 现状（已核对）

```
仓/待售/软件/
├── figma/
│   ├── figma - mac版/
│   ├── figma - win版/
│   └── figma - 浏览器插件/
├── figma_20261006_192135/   ← organize 残留空目录
└── figma_20261006_192543/   ← organize 残留空目录
```

**你的想法和现有结构是一致的** —— `figma - mac版` / `figma - win版` 已经是这个约定，只是还缺"形态"这一层。

### 建议结构（三层封顶）

```
仓/待售/软件/
└── Topaz Video/
    ├── Topaz Video - windows版/
    │   ├── 便携版/
    │   │   └── Topaz Video 1.7.1 中文汉化绿色便携版.zip
    │   └── 安装版/
    │       ├── Topaz Video 1.7.1 官方安装包 (x64).msi
    │       └── Topaz Video 1.7.x 补丁.zip
    └── Topaz Video - mac版/
        ├── Topaz Video 1.7.1 安装包 (Apple芯片).pkg
        ├── Topaz Video 1.7.1 安装包 (Intel).pkg
        └── Topaz Video 1.7.x 补丁.zip
```

同一结构复制到 `Topaz Photo/`、`Topaz Gigapixel/` 即可。

**为什么 Mac 侧不再分「便携版/安装版」**：macOS 的 app 基本都是拖拽即用，没有 Windows 那种"绿色便携 vs 直装"的区别。硬套会造出不存在的分类。Mac 侧真正的区分是**芯片**（Apple / Intel），所以直接写在文件名上、不再开目录。

> 上面是提议稿；**实际建成的目录与最终命名规范见第五、六节**。
> 与提议稿的一处修正：Mac 安装包实际是 `.pkg` 而非 `.dmg`（见第三节）。

## 六、命名规范（最终版）

1. **平台档目录统一后缀**：` - windows版` / ` - mac版`（已按此统一）
2. ⚠️ **目录名与文件名避开**：`破解` `免费` `永久` `全网最低` `可商用`
   —— 闲鱼违规或限流词，**分享出去的页面买家能看到**。
   要表达同义时用：`补丁` `汉化版` `便携版` `直装版` `激活工具`
3. **版本号必须写进文件名**（同软件多版本并存，且跨代版本号不可比较）
4. **架构/芯片写清楚**：`(Apple芯片)` `(Intel)` `(x64)`
5. **层级不超过 3 层**：`软件名` → `平台档` → `形态`

### Mac 侧为什么不分「便携版/安装版」

macOS 的 app 基本都是拖拽即用，没有 Windows 那种"绿色便携 vs 直装"的区别，硬套会造出不存在的分类。
Mac 侧真正的区分是**芯片**——按第 1 条已定的方案写在文件名上（`-arm64` / `-x86_64`），不再开目录。

### 一个已验证的好消息：改名不会弄坏已生成的分享链接

百度分享链接按**文件 fs_id** 记录，与路径名无关。
验证方式：改名后用链接本身读内容，仍能正常列出，且显示新名字。
→ 所以 `figma - win版` → `figma - windows版` 之后，已上架 Figma 商品的发货链接**没有受影响**。

## 七、补充 Mac 来源：repackmac.com（已采集）

上一节列的 5 个第三方 Mac 站里，`repackmac.com` 先做了采集器。**这个站比 423down 更好抓**。

### 为什么好抓：它开了 WordPress REST API

```
/wp-json/wp/v2/posts?per_page=100&page=N&_embed=1
```

正文（含下载信息卡）和封面图都在接口返回里 → **全站 800 篇只要 8 个请求**，不需要逐篇抓详情页。
`per_page` 上限实测 = 100（给 200 返 `HTTP 400`）。

### 实测结果（2026-10-08）

| 项 | 值 |
|---|---|
| 全站文章 | **800 篇**（`/category/macos/` 只是其中 558 篇） |
| 成功解析 | 800 篇 / **541 个产品** |
| 有可用下载链接 | **792 篇** |
| 下载源 | FileNest 614 / MediaFire 144 / torrentmac 33 / Mail.ru Cloud 1 |
| 装包类型 | `.dmg` 106 / `.iso` 3（老文章无信息卡，取不到文件名） |
| 同一产品多篇 | **156 个**（站点也按版本拆文章，最多的是 Cookie 9 篇） |

### ⚠️ 四个必须处理的坑（都踩过）

1. **站点有两套模板**，按时间切换（实测 2026-05-11 前后）：
   - 新：`Name: … / Size: … / Files: …`
   - 旧：`App Name: … / File Size: … / Package: …`
   而且旧的三个标签会**挤在同一行**。所以不能按行取，要**扫描所有标签位置、取相邻标签之间的值**。
   早期版本只认新标签 → 78% 的文章被误判为"无信息卡"。

2. **`Files` 字段不能用 `split(/(?=…\.dmg…\[)/)` 拆** —— 前瞻没有边界锚点，
   `[^\s\[\]]+\.dmg` 在 `macOS.dmg[` 的**每一个字符位置**都能匹配，结果把 `macOS` 拆成 m/a/c/O/S。

3. **扩展名不能取"最后一段"**：
   - 站点给自己的文件名加了标记：`Unite Pro 1.4 [EDiSO].dmg.repackmac` → 真实扩展名是 `.dmg`
   - 文件名以版本号结尾时误判：`TinkerTool System 9.89` → `.89`
   → 用白名单（dmg/pkg/iso/zip/rar/7z/tar/gz/xip/sit/app/exe/msi）取。

4. **下载链接的包装与噪声**：
   - `torrentmac.net/downloads/?link=<base64>` → 解出来多半是 **filenest.pro / filenest.cc**（注意有多个后缀）
   - 只靠"链接文字含 download"挡不住**厂商自己的产品页**（如 `4kdownload.com/products/…`）
     → 改成：命中托管域名白名单，或「下载按钮 + 分享型路径」

### ⚠️ 这些下载源国内基本打不开

MediaFire / FileNest 都是国外网盘。**这个站的价值是"拿到安装包原文件"**——
拿到后必须自己转存到百度网盘再上架。脚本里给每条记录标了 `needs_reupload`。

### 用法

```bash
npm run soft:repack -- fetch macos   # 只抓 macos 分类（558 篇）
npm run soft:repack -- fetch all     # 全站（800 篇）
npm run soft:repack -- parse
npm run soft:repack -- report        # 出 resources.json / resources.csv / index.html
```

产物里每条都给了按本方案算好的 `target_dir`（`仓/待售/软件/<产品>/<产品> - mac版`）。
